# FlowSketch — результат этапа 1

Дата: 13 октября 2026, Asia/Bishkek. Этап технических экспериментов выполнен: на этом Windows-компьютере работает цепочка «C++ → реальный Clang AST/CFG → модель переходов → раскладка → SVG/PDF/PNG». Выбранный подход подходит для перехода к прототипу; открытые ограничения ниже остаются задачами реализации. Этот результат не является приёмкой всей версии 1.

Публичный список задач: [FlowSketch roadmap](../ROADMAP.md). Проект и правила продолжения — в `README.md` и `AGENTS.md`.

Счётчики разделены: синтаксический smoke не считается готовой схемой; геометрические fixtures не доказывают семантику C++; основной корпус из 20 случаев не подменяет матрицу T01–T50 из ТЗ.

Clang используется с `-std=c++17 -pedantic-errors -Werror=return-type`. Пользовательский C++ нигде не линкуется и не исполняется. Проверены for/while/do, continue и break, switch/fallthrough/no-default, встроенные &&/||, ранний return, if/else и неявный return 0 в main. Управляющий макрос, volatile, ошибка синтаксиса, пропущенный возврат и непрозрачный вызов без declaration metadata отклоняются явно. Работа с STL сейчас подтверждена только на уровне разбора заголовков, а не построения их учебных блоков.

Исходные диапазоны сверены с точными UTF-8 срезами. `offsetEncoding` и `columnEncoding` равны `utf8-bytes`; строки начинаются с 1, конец диапазона исключающий. Преобразование колонок в UTF-16 для редактора остаётся задачей интерфейса.

## Toolchain и принятые технические решения

1. Анализ программы основываем на Clang, а не на распознавании C++ регулярными выражениями. Для эксперимента загружен локальный [llvm-mingw UCRT x86_64, release 20261006](https://github.com/mstorsjo/llvm-mingw/releases/tag/20261006), Clang 23.1.3. Версия, источник и SHA256 записаны в `spikes/clang/toolchain.json`; архив совпал с опубликованным digest. PATH и registry системы не менялись.
2. Профиль заголовков задан явно и очищает окружение child process от VS/SDK/include переменных. Три include-пути находятся внутри toolchain. Реально разобраны iostream, vector, string, algorithm и cmath с использованием соответствующих операций. Это подтверждает выбранную конфигурацию на данном хосте; чистая Windows проверяется отдельно.
3. ELKjs 0.12.0 размещает измеренные фигуры с фиксированными портами и ортогональными маршрутами. Обычное cycle breaking могло поднимать тело выше условия; принят порядок узлов по прямым переходам и `MODEL_ORDER`. Обратность задаётся `role:'back'` либо отдельным `layoutHint:'back'`. Сам `continue` не означает обратное ребро: в for он идёт к increment, в do — к нижней проверке. Все рёбра остаются в модели и сцене.
4. Размеры фигур зависят от метрик поставляемого шрифта. Проверяются настоящая внутренняя область ромба, отсутствие наложений, стрелок через посторонние фигуры, потерянных подписей и оторванных портов. Автоматическая раскладка сохраняет смысловые данные.
5. SVG, PDF и PNG используют одну сцену и контуры шрифта Liberation Sans с кириллицей. Эксперимент экспорта: fontkit 2.0.4, PDFKit 0.20.2, resvg-js 2.6.2; версии закреплены lockfile. Лицензия шрифта и сведения о зависимостях лежат в `spikes/layout-export/fonts` и `THIRD_PARTY_NOTICES.md`.
6. Tauri 2 + React/TypeScript + ELK остаются кандидатами для приложения согласно ТЗ. Monaco, React Flow, Rust-команды и native LibTooling sidecar предстоит проверить в настоящем Windows-окне. Node/PDFKit/native npm addon этого эксперимента ещё не подтверждают реализацию в WebView2 или конечную Windows-поставку.

Форматы CLI filtered AST JSON и `debug.DumpCFG` закреплены данным toolchain и применяются только в эксперименте. Перед расширением поддержки нужен native LibTooling-анализатор с полными сведениями о выбранной функции и вызываемых декларациях, версиями протокола, ревизиями исходника и ограничением вывода. Он реализуется отдельной задачей ANALYZER-01; перенос экспериментального CLI интерфейса в продукт без этого контракта не принят.

## Независимая проверка экспорта

PDF прочитан pypdf, затем отрендерен Poppler при 96 DPI и сопоставлен с PNG от resvg. В пяти геометрических случаях совпадение тёмного переднего плана IoU составило 0,904–0,976; в двух интеграционных случаях — 0,984. Допускается разница сглаживания; порог проверки — 0,85. Это проверка геометрии файлов, а не OCR или доказательство алгоритма.

Проверены размер страницы, отсутствие raster XObjects в PDF, Unicode metadata SVG и покрытие кириллицы шрифтом. PNG с длинными русскими подписями и независимо отрендеренный PDF sumOdd также просмотрены визуально: текст не обрезан, ветви Да/Нет читаются, возврат цикла не пересекает посторонние блоки.

Образец из реального C++: `spikes/integration/sum-odd.cpp`, `spikes/integration/out/sumOdd.svg`, `.pdf`, `.png`. Сцена содержит 10 узлов и 11 рёбер, размер 574×1006 логических px. `continue` ведёт к `++i`, затем к `i <= n`; инициализация не повторяется; false-ветвь ведёт к return s и завершению.

## Открытые ограничения и следующий этап

- **LAYOUT-02:** синтетическая схема на 200 блоков занимает 15899×4776, около 75,9 млн пикселей. PNG 1× отклонён по пределу 64 млн; SVG/PDF сохранены. Один эксперимент с распределёнными портами также превысил лимит. Нужны более компактные structured regions и нагрузка из репрезентативного C++; шрифт не уменьшаем для скрытого обхода лимита.
- **ANALYZER-01 / SEMANTICS-01:** реализовать native протокол и полную матрицу из 50 случаев, профили STL/I/O, выбор функции и диагностику контекста. Перегрузки/пространства имён, if-init, range-for, RAII, макросы и full declaration metadata текущим адаптером не подтверждены.
- **TAURI-01–06:** Rust пока отсутствует; VS C++ tools и WebView2 найдены. Следующий шаг — подготовить Rust, создать Tauri-окно с принятым дизайном и проверить редактор, .cpp, фоновые задания, связь блока с кодом, устаревание результата, оформление, сохранение и экспорт по ACC-05.
- **EXPORT-02:** PDF сейчас одностраничный в собственном размере; A4/A3 и граничные соединители не реализованы. Текст PDF — векторные контуры, поэтому не выделяется и не ищется. Запрошенные варианты PNG 2×/3×, темы и стили предстоит проверить отдельно.
- **PACKAGE-01 / RELEASE-01:** чистые Windows 10/11 без Node/Rust/VS/SDK и сети, варианты WebView2 и офлайн-установщик ещё не проверены.
- **WINDOWS-01 и архитектурные лимиты:** DPI/keyboard/reduced motion, 20-run p95, интерактивный renderer, закрепления, crossing bridges, cancel ≤1 s, Windows Job Object, memory budget и VFS allowlist остаются последующими проверками. Текущие CLI таймауты не являются приёмкой полного общего deadline 20 s.

Повторяемые команды и зависимости проверок приведены в `README.md`. `scripts/verify-stage1.ps1` собирает их в один последовательный запуск; синтаксис PowerShell проверен. На этом этапе команды выполнялись по отдельности после изменений и устранения найденных проблем, единый wrapper целиком отдельно не запускался.
